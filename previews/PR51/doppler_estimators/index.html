Doppler estimators and loop filters

A Doppler estimator closes the carrier and code loops. Its configuration (loop filter types and bandwidths) is a plain value, a subtype of AbstractDopplerEstimator; the per-satellite state it advances is created with init_estimator_state. Every estimator is stepped with the same call,

state, carrier_doppler, code_doppler = step_loop(estimator, state, record, words, landing_sample)

where record is a LoopRecord, words is the replica frequency the record was produced under (a FixedNCOWord for a software correlator, the channel's NCOTimeline for a hardware one) and landing_sample is the sample the new command takes effect at, or NO_LANDING_SAMPLE for "at the end of each record".

A host steps every record of a satellite, of every signal it tracks. The state remembers the driver it was initialised with: the driver's records close the loops, and the scalar loops leave any other record (a passenger, such as the data component of a pilot + data pair) to the host, returning the state unchanged and the command in force.

  • ConventionalPLLAndDLL: a PLL and a carrier-aided DLL.
  • ConventionalAssistedPLLAndDLL: the same with an FLL assisting the PLL until phase lock (see Carrier-loop staging), to pull in larger initial frequency errors. The default in Tracking.jl.
  • NCOReferencedPLLAndDLL: stays stable when its correction takes effect only several records later, as with a hardware NCO. With a fixed word and no landing sample it is the FLL-assisted conventional loop at the same bandwidths.

The bandwidth rules (default_wide_carrier_loop_filter_bandwidth, effective_carrier_loop_filter_bandwidth, …) keep the loops stable for a given integration time; the integration-length rules (calc_num_code_blocks_to_integrate, …) say how long a signal may be integrated coherently once its bit or secondary code has been found.

The per-record fold

apply_record advances one signal component's SignalLoopState (its prompt filter, C/N₀ estimator and bit buffer) by one record, so every caller does it the same way.

TrackingLoops.SignalLoopState — Type
SignalLoopState(signal; num_prompts_for_cn0_estimation = 100, cn0_estimator,
                post_corr_filter)

The per-record state of one signal component on a satellite: bit buffer, C/N₀ estimator, post-correlation filter, the last filtered prompt (the FLL chains from it) and the last record's block count. Immutable, rebuilt per record by apply_record; the estimators own their buffers, so every component needs its own instance: one per signal of every satellite, driver and passengers alike.

TrackingLoops.apply_record — Function
apply_record(state::SignalLoopState, signal, prn, output, sampling_frequency,
             noise_density, noise_density_ready,
             driver_carrier_phase = get_carrier_phase_offset(signal);
             overlay_wiped = has_bit_or_secondary_code_been_found(state))
    -> (state, prompt, filtered_correlator, integrated_code_blocks, overshoot)

fold_record on a SignalLoopState. Returns the new state, the prompt, the filtered correlator the discriminators read, the blocks the record covered and overshoot: whether a post-sync record carried the bit accumulator past the bit boundary, so the buffer dropped sync and restarted its search (SYNC_LOST; JuliaGNSS/Tracking.jl#238). The new state keeps the filtered prompt and what the record did, for a LoopRecord built from it. Nothing here logs; the caller reports overshoot (Tracking.jl warns once per satellite).

driver_carrier_phase is the carrier-phase offset (get_carrier_phase_offset) of the satellite's estimator-driver signal; the bit-buffer prompt is de-rotated against it. The default (the signal's own) suits the driver; a passenger component (the data half of a pilot/data pair) must be handed the driver's.

The pre-sync prompts of an is_dataless_with_secondary_code signal must be primary-only, so that the sync's polarity is the prompt's sign once the overlay is wiped. For any other signal the sync polarity only fixes the soft bits' sign, which the Costas loop leaves ambiguous anyway, so a fixed secondary chip in the pre-sync replica is fine.

overlay_wiped says whether the record's replica wiped the secondary code at the synced phase; it defaults to the buffer having synced before the record. Pass false for a record after a sync it was not correlated for yet (e.g. one found earlier in the same fold): for a secondary-coded signal its prompt is kept out of the coherent sum, though its blocks are credited, it moves the secondary-code anchor and its polarity is 0.

Two- and four-quadrant discriminators

The carrier discriminators are two-quadrant (Costas) by default: they read a prompt and its negation alike, so a data bit or secondary-code chip flipping the prompt's sign does not disturb them, over ±1/4 cycle for the PLL and ±1/(4T) for the FLL. Where the replica wipes every sign modulation off the prompt (a dataless signal synced to its secondary code) the prompt's sign is known, and the estimators switch to the four-quadrant discriminators, over ±1/2 cycle and ±1/(2T), worth up to 6 dB of tracking threshold. The record's carrier_phase_polarity, the prompt's sign, says so; apply_record computes it into the SignalLoopState, and a LoopRecord built from that state carries it to the scalar and vector loops alike. A record whose polarity differs from the previous record's comes without a previous prompt, so the four-quadrant FLL never compares prompts across the switch.

GPS L1C-P and L5Q, Galileo E1C, E5a-Q, E5b-Q and E6-C, and BeiDou B1C-P and B2a-Q switch once their secondary code is synced; if the Costas loop slipped half a cycle between the sync and the switch, the four-quadrant PLL pulls the carrier phase over by half a cycle, after which the prompt agrees with the sign again. Data signals never switch, nor, for now, do the pilots without a secondary code (GPS L2 CL, Galileo E5a-QP), whose sync reads no sign. The NCO-referenced loop folds its predicted phase error into whichever range the record's PLL reads.

The sign rests on a contract with whoever correlates the records, a hardware correlator as much as Tracking.jl: until the sync, these signals' records (is_dataless_with_secondary_code) are primary-only. A replica carrying the same secondary chip on every block is fine once the host multiplies the records by that chip (Tracking.jl's carries chip 0 and multiplies by it). A negative chip left in makes the sync read the wrong sign, and on the switch the four-quadrant PLL pulls the carrier phase over by half a cycle.

Estimators

TrackingLoops.ConventionalPLLAndDLL — Type

Conventional PLL and DLL Doppler estimator. Configuration only; per-satellite state is a SatConventionalPLLAndDLL from init_estimator_state.

CA and CO are the carrier and code loop filter types. The bandwidths (the PLL's wide and narrow, the FLL path's and the DLL's; see CarrierLoopStage) default to nothing, auto: sized per satellite from its driver signal via default_wide_carrier_loop_filter_bandwidth, default_narrow_carrier_loop_filter_bandwidth, default_fll_assist_loop_filter_bandwidth and default_code_loop_filter_bandwidth. Each is capped against the record's integration time at filter time (see LoopBandwidths), so longer integration needs no re-tuning.

TrackingLoops.LoopRecord — Type

One completed record as the loop-filter step sees it: the signal, the filtered (antenna-combined, normalised) correlator, the previous filtered prompt the FLL compares with, the record's span and block count, the band's sampling frequency, and fold_end, the end sample of the fold's last record, against which a landing sample is measured.

integrated_code_blocks must be at least 1: the carrier-loop staging sizes its phase-lock indicator's averages in records of that length and divides by it. A record built from a SignalLoopState always is (apply_record counts at least one block); a host building records otherwise must ensure it.

The four-quadrant FLL reads a prompt sign flip as half a cycle of rotation, so a record whose carrier_phase_polarity differs from the previous record's comes with previous_prompt = 0, giving no FLL reading, as for the first record. The constructor that takes a SignalLoopState applies this; a host building records otherwise passes 0 itself.

Fields for an estimator with per-satellite state of its own (VectorPLLAndDLL):

  • prn: the satellite (0 if unknown);
  • code_phase: the replica's code phase (chips) at sample_index, from the CorrelatorOutput (NaN if not reported).

For such an estimator sample_index / sampling_frequency must also be the time since an origin shared by every satellite of the band; a host whose correlator restarts its sample count passes the offset as sample_offset (added to sample_index and fold_end).

The rest summarises the signal's SignalLoopState after apply_record folded this record, for an estimator that decodes or weights by C/N₀ (the vector loop; the scalar loops ignore it):

  • bit_synced: whether the bit clock holds bit or secondary-code sync;
  • sync_change: whether this record found or lost it (SyncChange);
  • blocks_into_symbol: code blocks integrated into the current data symbol (0 before sync);
  • new_soft_bits: exactly the soft bits this record appended, a view of the bit buffer's vector valid for the call, so it does not matter when the host drains the buffer;
  • cn0_estimator: the signal's C/N₀ estimator, for estimate_cn0;
  • bit_polarity: the sign the bit clock's sync found its soft bits at (-1 if it negates the accumulated prompts' real part, +1 if it keeps it, 0 before sync).

carrier_phase_polarity is the prompt's sign where the replica wiped every sign modulation off it (a dataless signal synced to its secondary code), else 0. Nonzero, the PLL and the FLL read the record four-quadrant (pll_disc(...; polarity), fll_disc(...; polarity)); 0, two-quadrant.

The constructor taking a SignalLoopState fills all of this in. The others leave the bit clock unsynchronised, add no soft bits, carry a NoCN0Estimator and take carrier_phase_polarity as a keyword (0 by default): a host with its own per-signal state passes the one fold_record returned for the record.

TrackingLoops.NCOReferencedPLLAndDLL — Type
NCOReferencedPLLAndDLL(; wide_carrier_loop_filter_bandwidth = nothing,
                         narrow_carrier_loop_filter_bandwidth = nothing,
                         fll_assist_loop_filter_bandwidth = nothing,
                         code_loop_filter_bandwidth = nothing,
                         predict_landing = true)

FLL-assisted PLL and DLL Doppler estimator for a replica whose NCO words are applied with a known delay; the hardware-correlator receiver's default.

It is the ConventionalAssistedPLLAndDLL (same filters, gains, CarrierLoopStage staging and bandwidth defaults) with its internals referenced to the device NCO. The one different default is the wide PLL bandwidth: the narrow one (default_narrow_carrier_loop_filter_bandwidth), as a wider loop tolerates less command delay.

  1. Every record is attributed to the word that ran under it. Both discriminators are measured against the applied replica, so applied word + FLL discriminator is an absolute Doppler measurement; the DLL is normalised with the applied code word. The conventional loop does this too.
  2. The correction is sized for the moment it lands. The filter is fed the discriminators predicted at the new command's landing sample: the phase error (cycles) advanced by ∫ (f̂ − w(τ)) dτ over the words already scheduled, and the frequency measurement re-based onto the word running there.

With zero delay step 2 is the identity and the estimator is the conventional loop at the same bandwidths, inheriting its noise performance. predict_landing = false drops step 2, making it arithmetically the ConventionalAssistedPLLAndDLL: the documented negative control, which fails like it at a few epochs of delay.

TrackingLoops.phase_lock_indicator — Method
phase_lock_indicator(state) -> Float64

The latest phase-lock indicator of a scalar estimator's per-satellite state, or of a VectorPLLAndDLL's (in the vector loop its residual PLL's, on the prompts it rotated; out of it the inner loop's), which the carrier-loop staging reads (see CarrierLoopStage): ⟨I² − Q²⟩ / A² of the driver's prompts, an estimate of cos 2φ for the carrier phase error φ (1 in lock, 0 for a spinning phase), averaged over 0.1 s or 25 records, whichever is longer. NaN until the averages span that time.

Carrier-loop staging

The scalar loops stage their carrier loop on phase lock: FLL-assisted at the wide PLL bandwidth, then a pure PLL at the wide bandwidth, then narrow, each stage moving on once the phase-lock indicator (phase_lock_indicator) has read lock (phase_locked: at least 0.5, an RMS phase error of about 30°) long enough. The stages and when they advance are given under CarrierLoopStage; in the vector loop, see The carrier in the vector loop.

A wider loop tolerates less command delay: at 50 Hz the conventional loop holds through three records of delay. The NCOReferencedPLLAndDLL, meant for hardware correlators whose commands land records later, therefore pulls in at the narrow 18 Hz by default.

TrackingLoops.CarrierLoopStage — Type
CarrierLoopStage

The stage of a satellite's carrier loop in the scalar estimators' per-satellite state (see carrier_loop_stage):

  • FLL_ASSISTED_PLL: FLL-assisted PLL at the wide bandwidth (default_wide_carrier_loop_filter_bandwidth), its FLL path at default_fll_assist_loop_filter_bandwidth, until the phase-lock indicator (phase_lock_indicator) has read lock (phase_locked) without a break for one time constant of its averages: phase lock implies a converged Doppler;
  • WIDE_PLL: PLL alone at the wide bandwidth, the FLL discriminator no longer formed, until lock has held unbroken for another four time constants;
  • NARROW_PLL: PLL alone at the narrow bandwidth (default_narrow_carrier_loop_filter_bandwidth);
  • VECTOR_LOOP: no loop filter on the carrier NCO, which the navigation filter sets while the satellite is in the vector loop; its residual PLL follows the carrier (see VectorPLLAndDLL's residual_pll_loop_filter_bandwidth). The scalar staging never reaches it; only a satellite in the vector loop reports it.

A filter without an FLL path starts at WIDE_PLL. Dropping the FLL feeds the assisted filter a zero FLL input, which is exactly the third-order PLL (same state, same coefficients), so the switch is free (Kaplan & Hegarty §5.5). Dropping the FLL and narrowing are separate steps: narrowing while the loop still settles from the FLL's last correction risks the lock.

Each driver record's prompt advances the indicator, and the stage it reaches applies from the next record. Stages only advance: a loop that loses lock keeps the narrow PLL. init_estimator_state starts them over, as does a satellite's release from the vector loop; reset_estimator_state keeps them (a handoff to a new integration length, say, keeps the lock). In the vector loop the staging stands still.

Loop-filter bandwidths

The PLL pulls in at a wide 50 Hz and narrows to 18 Hz once phase lock has held; the FLL path of the FLL-assisted filter runs at 5 Hz while it is in use, and the code loop at 1 Hz, all for every signal. All are one-sided noise bandwidths BL (Kaplan & Hegarty), so they plug into the usual jitter and dynamic-stress formulas: the carrier filter is fed the phase error in cycles and the FLL error in Hz. 18 Hz is the third-order PLL bandwidth of the literature (Kaplan & Hegarty Table 5.6, Pany Table 3.3; Borre et al. quote about 20 Hz), none of which scales it with the primary code period: thermal jitter and dynamic stress, which set the bandwidth, do not depend on it.

Stability cap

Stability does depend on the loop update interval Δt, so at filter time every bandwidth, default or explicit, is capped against the record's integration time (effective_carrier_loop_filter_bandwidth, effective_fll_assist_loop_filter_bandwidth, effective_code_loop_filter_bandwidth). The cap only ever narrows a loop.

BL_pll  = min(BL_pll_configured,  0.09  / Δt)   # wide and narrow alike
BL_fll  = min(BL_fll_configured,  0.02  / Δt)
BL_code = min(BL_code_configured, 0.018 / Δt)

The default FLL-assisted third-order carrier filter diverges at BL · Δt ≈ 0.4 (the plain third-order one at ≈ 0.43). Below that, the loop's actual noise bandwidth runs wider than configured:

The PLL cap of 0.09 keeps the loop within 25 % of its configured bandwidth with about 4× stability margin, at the wide and the narrow bandwidth alike. It is the product of Kaplan & Hegarty's third-order design example (18 Hz at 5 ms) and matches GNSS-SDR's narrow post-sync bandwidths (5 Hz at 20 ms). A tighter cap on the narrow bandwidth would buy little: at 20 ms and 30 dB-Hz the thermal jitter is about 4° at 4.5 Hz and 2.6° at 2 Hz, while a TCXO's jitter (Allan deviation 1e-10, GPS L1) grows from about 6° to 13° and the jerk the loop tolerates falls with BL³. TrackingLoops.max_num_code_blocks_to_integrate — Method
max_num_code_blocks_to_integrate(signal)

Longest coherent integration, in primary code blocks, that signal's own structure allows — the ceiling calc_num_code_blocks_to_integrate clamps a satellite's preferred integration length against.

One full symbol: the data-bit period for data-bearing signals, or the secondary-code period for pilots (data_frequency == 0, e.g. GPS L1C-P). Integrating past it would straddle a symbol boundary and average two opposite signs away.

The default degenerates to a single block for a signal that has neither a multi-block data bit nor an overlay; Galileo E5a-QP overrides it to a whole 31-block code cycle (see galileo/e5a_qp.jl). GPS L2CL is the same shape and deliberately keeps the default: its 1.5 s primary period is already a whole coherent integration.
