Doppler estimators and loop filters

A Doppler estimator closes the carrier and code loops. Its configuration — loop filter types and bandwidths — is a plain value, a subtype of AbstractDopplerEstimator; the per-satellite state it advances is created with init_estimator_state. Every estimator is stepped with the same call,

state, carrier_doppler, code_doppler = step_loop(estimator, state, record, words, landing_sample)

where record is a LoopRecord, words is the replica frequency the record was produced under — a FixedNCOWord for a software correlator, the channel's NCOTimeline for a hardware one — and landing_sample is the sample the new command takes effect at, or NO_LANDING_SAMPLE for "at the end of each record".

A host steps every record of a satellite, of every signal it tracks. The estimator state remembers the driver it was initialised with: the driver's records close the loops, and the scalar loops leave any other record — a passenger, such as the data component of a pilot + data pair — to the host, returning the state unchanged and the command in force.

  • ConventionalPLLAndDLL — a PLL and a carrier-aided DLL.
  • ConventionalAssistedPLLAndDLL — the same, with the PLL assisted by an FLL, which pulls in larger initial frequency errors, until phase lock (see Carrier-loop staging). This is the default in Tracking.jl.
  • NCOReferencedPLLAndDLL — stays stable when the correction it computes only takes effect several records later, as it does with a hardware NCO. With a fixed word and no landing sample it is the conventional loop.

The bandwidth rules (default_wide_carrier_loop_filter_bandwidth, effective_carrier_loop_filter_bandwidth, …) keep the loops stable for a given integration time, and the integration-length rules (calc_num_code_blocks_to_integrate, …) say how long a signal may be integrated coherently once its bit or secondary code has been found.

The per-record fold

apply_record advances one signal component's SignalLoopState — its prompt filter, C/N₀ estimator and bit buffer — by one record, so every caller does it the same way.

TrackingLoops.SignalLoopState — Type
SignalLoopState(signal; num_prompts_for_cn0_estimation = 100, cn0_estimator, post_corr_filter)

The per-record state of one signal component on a satellite: its bit buffer, C/N₀ estimator, post-correlation filter, the last filtered prompt (which the FLL discriminator chains from) and the block count of the last record. An immutable value, rebuilt by apply_record per record; the estimators buffer into vectors they own, so every component needs its own instance.

The host holds one per signal of every satellite — the driver and each passenger alike — and advances it with apply_record on every record. It also remembers what the last record did to the bit clock, which a LoopRecord built from the state hands to the estimator: last_sync_change (a SyncChange) and last_num_new_soft_bits, the soft bits that record appended; last_previous_prompt, the prompt the FLL compares that record's prompt with: the one before it, or 0 where the two records have another carrier phase polarity (see LoopRecord); and last_carrier_phase_polarity, the sign of that record's prompt where the replica wiped every sign modulation off it, 0 where it is unknown, which the four-quadrant carrier discriminators read it with.

Two- and four-quadrant discriminators

The carrier discriminators are two-quadrant (Costas) by default: they read a prompt and its negation alike, so a data bit or secondary-code chip flipping the prompt's sign does not disturb them, over ±1/4 cycle for the PLL and ±1/(4T) for the FLL. Where the replica wipes every sign modulation off the prompt — a dataless signal synced to its secondary code — the prompt's sign is known, and the estimators switch to the four-quadrant discriminators, over ±1/2 cycle and ±1/(2T), worth up to 6 dB of tracking threshold. The record says so with its carrier_phase_polarity, the prompt's sign, which apply_record computes into the SignalLoopState and a LoopRecord built from that state carries, for the scalar loops and the vector loop alike. A record whose carrier phase polarity differs from the previous record's comes without a previous prompt, so the four-quadrant FLL never compares prompts across the switch.

GPS L1C-P and L5Q, Galileo E1C, E5a-Q, E5b-Q and E6-C, and BeiDou B1C-P and B2a-Q switch once their secondary code is synced. Data signals never do, nor, for now, do the pilots without a secondary code (GPS L2 CL, Galileo E5a-QP), whose sync reads no sign. The NCO-referenced loop folds its predicted phase error into whichever range the record's PLL reads.

The sign rests on a contract with whoever correlates the records: until the sync, the records of these signals (is_dataless_with_secondary_code) are primary-only, correlated with a replica that carries no secondary code. A replica that carries the same secondary chip on every block is fine once the host multiplies the records by that chip (Tracking.jl's carries chip 0, and multiplies by it). An external producer, a hardware correlator say, must keep to this as well. If its pre-sync replica carries a negative chip it does not multiply out, the sync reads the wrong sign, and on the switch the four-quadrant PLL pulls the carrier phase over by half a cycle.

Estimators

TrackingLoops.ConventionalPLLAndDLL — Type

Conventional Phase-Locked Loop (PLL) and Delay-Locked Loop (DLL) Doppler estimator. Configuration-only — per-satellite state is a SatConventionalPLLAndDLL, produced via init_estimator_state.

Type parameters CA and CO select the carrier and code loop filter types; the bandwidth fields configure the loop bandwidths used when seeding new satellites: the PLL's wide bandwidth, which it pulls in at, and its narrow one, which it narrows to once phase lock has held, the FLL-assist bandwidth of an FLL-assisted carrier filter's FLL path, and the code bandwidth (see CarrierLoopStage). Each bandwidth field is Maybe{typeof(1.0Hz)}: a nothing field (the default) means auto — the bandwidth is sized per satellite from its estimator-driver signal via default_wide_carrier_loop_filter_bandwidth, default_narrow_carrier_loop_filter_bandwidth, default_fll_assist_loop_filter_bandwidth and default_code_loop_filter_bandwidth. At filter time each is capped against the record's integration time (effective_carrier_loop_filter_bandwidth, effective_fll_assist_loop_filter_bandwidth, effective_code_loop_filter_bandwidth), so a longer coherent integration needs no re-tuning.

TrackingLoops.LoopRecord — Type

One completed record as the loop-filter step sees it: the signal it belongs to, the filtered (antenna-combined, normalised) correlator, the previous record's filtered prompt the FLL chains from, the record's span and the blocks it covered, the band's sampling frequency, and fold_end — the end sample of the last record of the fold this record belongs to, which is what a landing sample is measured against (every record of a fold maps onto the delay-free loop's record the same distance ahead).

integrated_code_blocks, the primary code blocks the record covered, must be at least 1: the carrier-loop staging sizes its phase-lock indicator's averages in records of that length and divides by it. A record built from a SignalLoopState always is, as apply_record counts at least one block; a host that builds records otherwise passes at least 1.

The four-quadrant FLL reads a sign flip between the previous and this record's prompt as half a cycle of rotation. A record whose carrier_phase_polarity differs from the previous record's therefore comes without a previous prompt (0), and the FLL gives no reading for it, as for the first record. The constructor that takes a SignalLoopState takes the previous prompt from the state (its last_previous_prompt), which applies this; a host that builds records otherwise passes 0 itself.

Two fields identify the record to an estimator that keeps per-satellite state of its own, as VectorPLLAndDLL does:

  • prn: the satellite (0 when the host does not say);
  • code_phase: the replica's code phase (chips) at sample_index, from the CorrelatorOutput (NaN when the producer does not report it).

For such an estimator sample_index / sampling_frequency must also be the time since one origin shared by every satellite of the band. A host whose correlator restarts its sample count passes that origin's offset as sample_offset to the constructor that takes a CorrelatorOutput; it is added to sample_index and fold_end.

The rest summarises the signal's SignalLoopState after apply_record folded this record into it, for an estimator that decodes or weights by C/N₀ (the vector loop; the scalar loops ignore it):

  • bit_synced: whether the bit clock holds the bit or secondary-code sync after this record;
  • sync_change: whether this record found or lost it (SyncChange);
  • blocks_into_symbol: the code blocks integrated into the current data symbol (0 before the sync);
  • new_soft_bits: exactly the soft bits this record appended — a view of the bit buffer's vector, valid for the duration of the call, so it does not matter when the host drains the buffer;
  • cn0_estimator: the signal's C/N₀ estimator, for estimate_cn0.

carrier_phase_polarity says how the carrier discriminators read the record: the sign of its prompt where the replica wiped every sign modulation off it — a dataless signal synced to its secondary code — and 0 where it is unknown. Nonzero, the PLL and the FLL read it four-quadrant (pll_disc(...; polarity), fll_disc(...; polarity)); 0, both stay two-quadrant.

Build such a record with the constructor that takes the state in place of the block count and the previous prompt: LoopRecord(signal, filtered_correlator, output, state, sampling_frequency). The other constructors leave the bit clock unsynchronised, add no soft bits, carry a NoCN0Estimator and take carrier_phase_polarity as a keyword, 0 by default: a host with its own per-signal state passes the one fold_record returned for the record.

TrackingLoops.NCOReferencedPLLAndDLL — Type
NCOReferencedPLLAndDLL(; wide_carrier_loop_filter_bandwidth = nothing,
                         narrow_carrier_loop_filter_bandwidth = nothing,
                         fll_assist_loop_filter_bandwidth = nothing,
                         code_loop_filter_bandwidth = nothing,
                         predict_landing = true)

FLL-assisted PLL and DLL Doppler estimator for a replica whose NCO words are applied with a known delay — the hardware-correlator receiver's default.

It is the ConventionalAssistedPLLAndDLL — the same third-order assisted bilinear carrier filter, the same second-order code filter, the same gains, the same staging (see CarrierLoopStage) and the same bandwidth defaults, but for the wide PLL bandwidth, which defaults to the narrow one (default_narrow_carrier_loop_filter_bandwidth), as a wider loop tolerates less command delay — with its loop internals referenced to the device NCO instead of to the word the filter last computed:

  1. Every record is attributed to the word that ran under it. The phase discriminator is measured against the applied replica by construction; the frequency discriminator is re-based onto it too, so applied word + FLL discriminator is an absolute measurement of the signal's Doppler. The DLL is normalised with the applied code word.
  2. The correction is sized for the moment it lands. The filter is stepped with the discriminators predicted at the landing sample of the new command: the measured phase error advanced by ∫ (f̂ − w(τ)) dτ cycles over the words already scheduled at the NCO, and the frequency measurement taken relative to the word that will be running there.

With zero delay both steps are the identity and the estimator is the conventional loop, so the software receiver's noise performance is inherited rather than re-tuned.

Step 1 is not specific to this estimator: the conventional step_loop reads the applied code word from words too, and both discriminators are measured against the replica that ran, so neither loop needs a correction for it. What sets this estimator apart is step 2, including the re-basing of the frequency measurement onto the word that will be running at landing. predict_landing = false drops step 2 and is then arithmetically the ConventionalAssistedPLLAndDLL: the documented negative control, which fails exactly like the conventional loop at a few epochs of delay.

Carrier-loop staging

The scalar loops stage their carrier loop on phase lock (CarrierLoopStage):

  • FLL-assisted PLL (FLL_ASSISTED_PLL) at the wide PLL bandwidth, its FLL path at its own FLL-assist bandwidth, until the phase-lock indicator has read lock for one time constant of its averages;
  • Wide PLL (WIDE_PLL): the FLL dropped, until the indicator has read lock for another four time constants;
  • Narrow PLL (NARROW_PLL) at the narrow bandwidth.

The phase-lock indicator (phase_lock_indicator) is ⟨I² − Q²⟩ / A², an estimate of cos 2φ, from exponential averages of the driver's prompts over 0.1 s or 25 records, whichever is longer. The signal power A² comes from the prompts' moments, √(2 M₂² − M₄), which the noise cancels from, so a locked loop does not read low at a low C/N₀. It reads lock at 0.5, an RMS phase error of about 30°. Dropping the FLL feeds the FLL-assisted filter a zero FLL input, which is exactly the third-order PLL, so the switch is free, and the FLL discriminator is no longer formed.

The stages only advance: a loop that loses lock keeps the narrow PLL. A satellite's release from the vector loop starts them over, so the scalar loop that takes over pulls in afresh. reset_estimator_state keeps them: it is the handoff to a new integration length, after which the re-seeded loop holds its lock at the stage it has reached, its bandwidths capped for the new length. A satellite the vector loop takes over runs at the narrow PLL there. Its FLL path carries the navigation filter's carrier correction at a bandwidth of its own, the vector FLL's 1 Hz (see Vector FLL).

A wider loop tolerates less command delay: at 50 Hz the conventional loop holds through three records of delay. The NCOReferencedPLLAndDLL, meant for hardware correlators whose commands land records later, therefore pulls in at the narrow 18 Hz by default.

TrackingLoops.CarrierLoopStage — Type
CarrierLoopStage

The stage of a satellite's carrier loop, held in the scalar estimators' per-satellite state (see carrier_loop_stage):

  • FLL_ASSISTED_PLL: the FLL-assisted PLL at the wide bandwidth (default_wide_carrier_loop_filter_bandwidth), its FLL path at the FLL-assist bandwidth (default_fll_assist_loop_filter_bandwidth), until the phase-lock indicator (phase_lock_indicator) has read lock for one time constant of its averages: the carrier phase is locked, so its Doppler has converged;
  • WIDE_PLL: the PLL alone at the wide bandwidth, until the indicator has read lock for another four time constants;
  • NARROW_PLL: the PLL alone at the narrow bandwidth (default_narrow_carrier_loop_filter_bandwidth).

A carrier filter without an FLL path starts at WIDE_PLL. Dropping the FLL feeds the FLL-assisted filter a zero FLL input, which is exactly the third-order PLL (same state, same coefficients), so the switch is free (Kaplan & Hegarty §5.5). Dropping the FLL and narrowing are separate steps: narrowing while the loop still settles from the FLL's last correction risks the lock.

The stages only advance. init_estimator_state starts them over, as does a satellite's release from the vector loop. reset_estimator_state keeps them, since a handoff to a new integration length, say, keeps the lock. While a satellite is in the vector loop its carrier loop runs at the narrow bandwidth, and carrier_loop_stage reports NARROW_PLL.

Loop-filter bandwidths

The PLL pulls in at a wide 50 Hz and narrows to 18 Hz once phase lock has held; the FLL path of the FLL-assisted filter runs at 5 Hz while it is in use, and the code bandwidth is a flat 1 Hz, all for every signal. All are one-sided noise bandwidths BL in the sense of Kaplan & Hegarty, so they plug into the usual jitter and dynamic-stress formulas: the carrier filter is fed the phase error in cycles and the FLL error in Hz. 18 Hz is the third-order PLL bandwidth of the literature (Kaplan & Hegarty Table 5.6, Pany Table 3.3; Borre et al. quote about 20 Hz), none of which scales it with the primary code period: thermal jitter and dynamic stress, which set the bandwidth, do not depend on it.

Stability cap

Stability does depend on the loop update interval Δt, so at filter time each bandwidth is capped against the record's actual integration time (effective_carrier_loop_filter_bandwidth, effective_fll_assist_loop_filter_bandwidth, effective_code_loop_filter_bandwidth). An explicit bandwidth is capped the same way; the cap only ever narrows a loop.

BL_pll  = min(BL_pll_configured,  0.09  / Δt)   # wide and narrow alike
BL_fll  = min(BL_fll_configured,  0.02  / Δt)
BL_code = min(BL_code_configured, 0.018 / Δt)

The default FLL-assisted third-order carrier filter diverges at BL · Δt ≈ 0.4 (the plain third-order one at ≈ 0.43). Below that, the loop's actual noise bandwidth runs wider than configured:

The PLL cap at 0.09 keeps the loop within 25 % of its configured bandwidth with about 4× stability margin, at the wide and the narrow bandwidth alike. It is the product of Kaplan & Hegarty's third-order design example (18 Hz at 5 ms) and matches GNSS-SDR's narrow post-sync bandwidths (5 Hz at 20 ms). A tighter cap on the narrow bandwidth would buy little: at 20 ms and 30 dB-Hz the thermal jitter is about 4° at 4.5 Hz and 2.6° at 2 Hz, while a TCXO's jitter (Allan deviation 1e-10, GPS L1) grows from about 6° to 13° and the jerk the loop tolerates falls with BL³. TrackingLoops.LoopBandwidths — Type
LoopBandwidths(; wide_carrier = 50Hz, narrow_carrier = 18Hz, fll_assist = 5Hz,
                 code = 1Hz, vector_fll = 1Hz)
LoopBandwidths(signal; wide_carrier, narrow_carrier, fll_assist, code, vector_fll)

The loop-filter bandwidths of a scalar estimator's per-satellite state: wide_carrier for the PLL until it narrows and narrow_carrier after (see CarrierLoopStage), fll_assist for the FLL path while the loop is FLL-assisted, code for the DLL, and vector_fll for the FLL path while a VectorPLLAndDLL feeds it the navigation filter's carrier correction. Given a signal, each bandwidth not given defaults to the signal's (default_wide_carrier_loop_filter_bandwidth, default_narrow_carrier_loop_filter_bandwidth, default_fll_assist_loop_filter_bandwidth, default_code_loop_filter_bandwidth, default_vector_fll_loop_filter_bandwidth), so methods of those for a signal type apply; without one, to the generic defaults. The four-argument positional form leaves vector_fll at its generic default. init_estimator_state resolves them from the estimator's, each nothing there from the driver signal's default. Each is capped at filter time, the vector FLL's against the navigation cycle time and the others against the record's integration time (see effective_carrier_loop_filter_bandwidth, effective_fll_assist_loop_filter_bandwidth, effective_code_loop_filter_bandwidth, effective_vector_fll_loop_filter_bandwidth).

TrackingLoops.default_vector_fll_loop_filter_bandwidth — Method
default_vector_fll_loop_filter_bandwidth(signal)

Recommended vector-FLL bandwidth for signal: 1 Hz, the noise bandwidth of the FLL branch of the carrier filter of a satellite in the vector loop (see VectorPLLAndDLL). The branch integrates the navigation filter's carrier correction, which is set once per navigation cycle (every 100 ms by default) and held for the cycle. So the loop it closes is sampled at 10 Hz and must sit well below that rate's 5 Hz Nyquist frequency. It must also sit well below the PLL's 18 Hz, so that the two branches do not share a band. 1 Hz is BL · T = 0.1 on the default cycle, where the sampled loop's noise bandwidth runs 18 % over the configured one (see MAX_VECTOR_FLL_LOOP_BANDWIDTH_CYCLE_PRODUCT), and it still removes a velocity error of the replica within about a second. The vector loop used to tie the FLL branch to the PLL's bandwidth (ω₀ / 4, 2.9 Hz at 18 Hz). That sampled loop has BL · T ≈ 0.3 and raised the replica's phase noise at 2–3 Hz. The FLL-assist bandwidth (default_fll_assist_loop_filter_bandwidth) is for pull-in and is not used here.

Capped at filter time by effective_vector_fll_loop_filter_bandwidth against the navigation cycle time. Override by defining a method for your signal type, or pass vector_fll_loop_filter_bandwidth = to VectorPLLAndDLL.

TrackingLoops.max_num_code_blocks_to_integrate — Method
max_num_code_blocks_to_integrate(signal)

Longest coherent integration, in primary code blocks, that signal's own structure allows — the ceiling calc_num_code_blocks_to_integrate clamps a satellite's preferred integration length against.

One full symbol: the data-bit period for data-bearing signals, or the secondary-code period for pilots (data_frequency == 0, e.g. GPS L1C-P). Integrating past it would straddle a symbol boundary and average two opposite signs away.

The default degenerates to a single block for a signal that has neither a multi-block data bit nor an overlay; Galileo E5a-QP overrides it to a whole 31-block code cycle (see galileo/e5a_qp.jl). GPS L2CL is the same shape and deliberately keeps the default: its 1.5 s primary period is already a whole coherent integration.
